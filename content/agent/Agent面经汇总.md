## 面试记录

### 上海与非智联科技 · Agent 开发实习 · 一面

**基本信息**

- 时间：6.25
- 岗位：Agent 开发实习
- 轮次：一面，约 30min，线上视频
- 公司背景：创业公司，算力 / IDC（GPU、机房）起家，现往 AI 应用层走；核心场景是**医疗**，对接上海三甲医院（如瑞金）做医疗 AI Coding / Agent，用「AI Coding + Agent」改造医院工作流（病例采集、疑难 case 收集、研究打分标注等）。面试官提到 **AI FDE**（最后一公里、把事情落到业务现场）这个概念。

**被问到的问题（按顺序）**

围绕项目（MewCode / ADC Coding Agent）深挖：

1. 自我介绍
2. 你这个项目相当于把 Claude Code 的结构复刻了一遍？（质疑原创性）
3. 你提到**两层压缩机制**，具体怎么实现的？
4. 压缩具体怎么做的？针对 N 轮对话怎么处理——每轮都压吗？
5. 怎么判断哪些语义 / 轮次是「重要」的？
6. 压缩中有没有遇到过「压不好导致输出变差」的情况？具体什么 case？
7. 这个压缩机制处理不了哪些**边界条件**？
8. **权限拦截**是怎么设计的？（几层、每层做什么）
9. 每一层具体的「目的 + 实现」能讲细一点吗？（命令拦截 / 正则已清楚）
10. **路径沙箱**解决什么问题？你通过什么方式让文件索引更精确？
11. **规则引擎**是干什么的？
12. LLM 适配的协议是通用的吧？（多厂商切换）
13. **记忆**怎么管理？存成什么文件 / 什么方式？什么时候被加载？
14. 记忆（用户偏好、项目知识）是在 ReAct 循环的**哪一步、什么时机**给到模型？
15. 上下文压缩发生时，提示词里的「用户问题 / 系统提示词 / 记忆 / CLAUDE.md / 工具技能」这几块**分别怎么被处理**？

AI Coding 实践经验：

16. 日常开发用什么模型、什么 IDE？
17. 用 AI Coding 有什么体验？踩过什么坑？经验总结？
18. 开发完之后，功能验收 / 验证有什么好做法？
19. （追问）Docker 为什么跟测试有关系？
20. 有没有基于 Claude Code / OpenClaw 这类产品做过工作流 / 任务流？
21. 之前没实习过吧？研一之后时间更可控？

**回答复盘（这次明显卡壳 / 答偏的点）**

- ⚠️ **「重要语义怎么判断」**：答得含糊，没给出明确判定标准，被追问后绕回去了。→ 该准备清晰回答：按轮次新近度 / 是否含工具结果 / 是否被后续引用来判断。
- ⚠️ **压缩的边界 case**：被追问「具体什么 case 压不好」答不上来，只能说"对话太多太杂"。→ 准备 1 个具体 case（如压缩丢了关键 `tool_result`，导致模型反复调同一个工具）。
- ❌ **规则引擎答错**：把「规则引擎」混成了「权限模式（只读 / acceptEdits / plan）」，当场也意识到说错了。→ 规则引擎 = 用户级 / 项目级 / 本地级规则文件按 Tool 匹配 allow/deny，要和权限模式分清。
- ⚠️ **记忆 vs 落盘 / 压缩**：一开始把「落盘、压缩」当成记忆，被面试官纠正——落盘是系统 / 执行层操作，记忆指的是用户偏好、项目知识。
- ⚠️ **压缩时各部分分别怎么处理**：答得不完整，自己也承认"这个回答不是很好"，没讲清 CLAUDE.md / Skill（本身精简、基本不压）vs 历史对话（摘要压缩）的区别。

**反问环节**

- 问：能不能举一个很直接的医疗业务案例？→ 答：医院病例 / 疑难 case 采集、医学研究打分标注等工作流，传统方式费时（采一个病例医学生要 1 小时），AI 介入后通过 OCR / 扫描自动识别，逐步托管流程。
- 问：参与这种 AI 系统研发，和传统系统开发的差别在哪？→ 答：更贴近业务、偏定制化；通用 Claude Code 门槛高（医生学不了），未来会从通用走向定制化 Agent 层，类似 AI FDE 把事情落到业务现场。

**结果 & 感受**

- 结果：依旧拷打
- 教训：
	- 项目里「压缩 / 记忆 / 权限」三块被往细里追问时，几处只停留在概念、给不出实现细节和具体 case；规则引擎与权限模式概念混淆。下次重点把这三块的**实现细节 + 踩坑案例**背熟。
	- 我在反问环节可以做一些关于面试感受的询问

### 上海张量记忆 · Agent 开发实习 · 一面

**基本信息**

- 时间：6.30
- 岗位：Agent 开发实习
- 轮次：一面，约 30min，线上视频
- 公司背景：主营 **AI Memory**（记忆张量 / 张量记忆）。面试官偏技术、问得很细，主要围绕 **Claude Code 源码 + 上下文工程**深挖。

**被问到的问题（按顺序）**

闲聊 / 背景：

1. 自我介绍
2. 研究生年级、实验室情况（导师职称、是否放养、能否支持实习）
3. 本科计算机为什么选华师大数据科学？属于哪个学院？
4. 目前是否在上课？硕士论文 / 小论文要求？
5. 能实习多久？开学后实验室是否要求坐班 / 查岗？

项目（MewCode / Coding Agent）深挖：

6. 这个项目是开源项目还是自己做的？为什么做 coding agent？
7. 简单介绍项目（功能 + 五层架构 + 上下文管理 + 权限 + multi-agent）
8. 这是参考 Claude Code 源码的设计吧？为什么选 coding agent 这个方向？
9. 讲讲 Claude Code 源码设计上吸引你的几个亮点？
10. **Claude Code 在 Context Engineering（上下文工程）上是怎么设计的？**
11. **200K 上下文是写死 / 绑定的吗？不同模型上下文不一样，为什么只支持 200K？**
12. **上下文由哪几部分构成？怎么保证 KV cache 缓存命中率？**
13. **调用 LLM 时，哪些上下文常驻？哪些在触及模型上限时被压缩？**
14. **你的滚动压缩策略是什么？是保留最近 5 轮吗？**
15. 你这套框架设计上有什么亮点？（→ 引出五层权限 + multi-agent + plan mode）
16. **Claude Code 的 plan 模式和 Cursor / Codex 有什么区别？**

其他背景：

17. 研一课程有哪些？有和大模型相关的吗？
18. 蓝桥杯省三是什么项目？（个人 C++ 算法竞赛）

**回答复盘（卡壳 / 答偏的点）**

- ⚠️ **「200K 是不是写死的 / 为什么只支持 200K」**：答成了"适中方案"，没答到点。→ 正确：200K 是**模型（Claude）的上下文窗口**，不是 Claude Code 写死的；harness 按**当前所用模型的窗口大小**动态算压缩阈值（换 1M 窗口的模型阈值就跟着变）。被追问"不同模型窗口不一样吗"时没顺势讲清。
- ⚠️ **「怎么保证 KV cache 命中率」**：没真正答到。→ 正确方向：**稳定前缀走缓存**——system prompt、工具定义这些固定内容放最前、长期不变，命中 prompt cache；**动态信息（system-reminder、时间等）放后面**、用 reminder 形式注入，不破坏前面的缓存前缀；压缩 / 改历史会让缓存失效，所以要控制压缩频率。
- ⚠️ **「哪些常驻 / 哪些被压缩」**：答了落盘 + 截断最前 1/5，但不够系统，没分层讲清「system / 工具 / 记忆 / CLAUDE.md（基本常驻不压）vs 历史对话（摘要压缩）」（和上一家被问的是同一类）。
- ⚠️ **「plan 模式 vs Cursor / Codex」**：答"感受不到差异"。→ 可答：Claude Code 的 plan mode 是**工具层强制只读**（写文件 / 跑命令的工具直接禁用），不是只靠 prompt 叮嘱；把"自动执行的边界"交给用户先确认再执行。
- ⚠️ 整体：上下文工程被往细里追问时（200K 来源、KV cache、压缩边界），多停留在概念、给不出准确机制——和上一家（与非智联）暴露的是**同一类问题**。

**反问环节**

- 问：公司是叫记忆张量吗？业务和 AI Memory 相关性强吗？→ 答：是，主营 Memory 方向。
- 问：对我这次面试有什么改进建议？→ 面试官给了 3 点：① 把现在 **Harness 相关的主要方向**了解清楚（第一步）；② Claude Code 这种优秀源码的**设计架构、差异性**要摸清楚；③ 多在**开源项目 / 社区**提问、关注大家的问题点和研究方向，成长更快。

**结果 & 感受**

- 结果：待定（面试官结尾给的是偏指导性的"成长建议"）
- 教训：
	- 上下文工程是这家的重点拷打区，**200K 的由来、KV cache 命中率、压缩边界**三个点都没给出准确机制 → 要把"上下文工程"从"会背概念"升级到"讲得清机制"。
	- 反问环节问"改进建议"效果不错，拿到了具体方向，可以继续用。

### 上海平行时空科技 · Agent 开发实习 · 一面

**基本信息**

- 时间：2026.7.1（具体日期待确认）
- 岗位：Agent 开发实习
- 轮次：一面，约 30min，线上视频（腾讯会议，全程网络卡顿，多次影响看题 / 共享屏幕）
- 公司背景：**平行时空科技有限公司**，做 To B 的 AI 应用落地。负责人杨超（几位创始人，曾在硅谷工作）；已中无锡「飞控人才」（2024）+ 市一级人才。现有场景覆盖**旅游 / 法律 / 无人机**等行业，近期想做**面向海外**的新产品。面试偏**基本功 + 概念**考察（MCP / 多智能体 / git worktree / RAG），并现场手撕算法题。

**被问到的问题（按顺序）**

背景：

1. 自我介绍
2. 之前没实习过吧？
3. 看到你有一个终端的项目，是个人爱好做的吧？

概念深挖：

4. 什么是 **MCP**？你调用过 MCP 吗？自己写过 MCP server 吗？
5. MCP 跟 **Function Calling** 有什么区别？
6. 你那个**多智能体**协作，你觉得多智能体好在哪 / 解决什么？
7. 讲一下什么是 **git worktree**？
8. 你做 RAG 的时候用什么**向量数据库**？（→ 我项目没做 RAG）

基本功 / 手撕算法：

9. 项目经验少的话就考考基本功——你平常用什么语言写代码？
10. **手撕算法题**：给一个单词列表和整数 K，返回出现次数最多的 K 个单词（频率相同按字典序）。面试官发的是 **C++ 函数签名**，要求关掉 AI 补全、共享屏幕现写。→ 本地没配 C++ 编译环境、STL 基本写法（map 迭代 / 排序）记不清、依赖自动补全，最终没写出可编译代码，只口述了思路。
11. 时间复杂度分析？（我答排序做法 O(n log n)）

**回答复盘（这次明显失分 / 答偏的点）**

- ❌ **手撕算法（最大失分点）**：本地没配 C++ 环境 + STL 裸写生疏 + 过度依赖 AI 补全 → 一道 LeetCode Medium（Top K Frequent Words）都写不出可编译代码，只能讲思路。恰好撞在面试官「我们要基本功很好的人」的招人标准上。→ 必须补：本地配好编译环境、脱离 AI 手写常见算法、熟练 STL（`unordered_map` / `priority_queue` / `sort` 自定义比较）。
- ⚠️ **MCP 概念答偏**：说成「让大模型和工具调用的**频次**减少」「N×M 变复用」，没落到点。→ 正确：MCP 是**标准化「Agent ↔ 外部工具 / 数据源」连接的开放协议**，把 M 个应用 × N 个工具的重复对接从 **M×N 降到 M+N**，不是「减少调用频次」。
- ⚠️ **没写过 MCP server**：诚实但暴露实操缺失，只调用过、没从零写过。
- ⚠️ **git worktree**：直接跳到「让每个 worker 在独立环境工作」，没说清 worktree 本身是什么（**同一仓库挂多个工作目录、共享 `.git`、各检出不同分支**）。
- ❌ **RAG / 向量数据库**：项目没做过、向量库也不清楚 → 直接答「不清楚」。→ 至少要能讲清 RAG 流程 + 常见向量库（FAISS / Milvus / Chroma / Qdrant / pgvector），并能说清「coding agent 为什么用 grep / 文件检索而非向量 RAG」。
- ⚠️ **算法最优解**：只给了排序 O(n log n)，没想到**堆 O(n log k)** 的更优解。

**反问环节**

- 问：给刚入门 Agent 方向的人一些建议？→ 面试官讲了他们的**招人标准**：① 要么**基本功很好、很聪明**，即使没经验也能很快上手；② 要么在**某个细分领域有很深的经验**（别人没做过的事，如微调 / 训练 / 很深的项目），且方向和他们契合。

**结果 & 感受**

- 结果：❌ 
- 教训：
	- **基本功是这家的红线**：脱离 AI 手写算法 + STL 生疏直接暴露，面试官明确说招「基本功很好」的人 → 这块必须补硬。
	- **概念要讲精准**：MCP 说成「减少调用频次」、git worktree 没讲清定义 —— 会用 ≠ 讲得清。
	- RAG / 向量库是空白，先补基础概念，能诚实作答但要讲得出所以然。

### 上海链接者集团 · Agent 开发实习 · 一面

**基本信息**

- 时间：2026.7.3
- 岗位：Agent 开发实习
- 轮次：一面，约 40min，线上视频
- 面试官：两位——先是**产品 / HR**（聊生态、花费、AI Coding 体验），后是**技术**（概念深挖 + 项目拷打）
- 公司背景：上海链接者集团。整体偏「**概念基本功 + 结合业务 / 产品价值**」考察，技术面试官对 Claude Code 源码机制、RAG 很熟。

**被问到的问题（按顺序）**

产品 / HR 面试官（生态 & 实践）：

1. 自我介绍
2. 更详细讲技能掌握 + 项目经历（背景、承担的工程职责、怎么推进）
3. 这个项目是你自己做的吧？之前有实习过吗？
4. 你会看开源项目和最新技术，分享 1~2 个你在看的项目 / 技术？
5. 前段时间某 Agent 产品挺火，你玩过吗？你觉得这个东西怎么样？
6. 关于自己编写 **Skill**，你有了解吗？
7. 除了 Claude Code 还用过什么别的 AI 编程工具？
8. 你每个月在 AI 上花多少钱？那个档位够用吗？

技术面试官（概念 & 项目深挖）：

9. 你写 MewCode，是觉得 Claude Code 哪点不好用，还是学习用途？写的过程中发现什么问题？
10. 介绍几种常见的 **Agent 范式** + 它们的结构？
11. 说一下 **Function Calling 和 MCP** 的区别？
12. **MCP 和 Skill** 的区别？什么时候用 MCP、什么时候用 Skill？各自特点？
13. 说一下 **RAG 的完整流程**？
14. 你刚讲的是 workflow 里的 RAG，**在 Agent 里 RAG 一般怎么用**？（第一次没检索到想要的怎么办）
15. 你看过 Claude Code 代码，它里面**有没有用 RAG 检索**？
16. Claude Code **怎么逐步定位代码块**？比如某个文件没改，怎么定位到代码在多少行？
17. 你这个项目基于什么**框架**开发？（→ LangGraph）
18. 后端用 Python？有没有涉及**前端**？**数据库**会吗？
19. 你对哪方面比较感兴趣？以前做过**量化 / 金融交易**吗？
20. 介绍一下 Claude Code 的一些**命令 / 斜杠命令**？
21. 你觉得**什么时候该 compact，什么时候不该**？

**回答复盘（卡壳 / 答偏的点）**

- ❌ **MCP vs Skill（最明显失分）**：把 Skill 说成「memory 上的处理 / 拼接上下文」，没讲清。→ 正确：**MCP 给能力**（连接协议、M×N→M+N），**Skill 给方法**（知识 + 工作流、渐进式按需加载）；要接新外部能力用 MCP，要固化做事流程用 Skill，常混合用。
- ⚠️ **Agentic RAG 没接住**：面试官追问「workflow 的 RAG 讲完了，Agent 里 RAG 怎么用」，我绕回落盘 / 向量化，没答到点。→ 正确：workflow 的 RAG 是**固定一步**、召回不好没补救；Agent 把 **RAG 封装成一个工具**，在 ReAct 循环里**自主反复调用**、不满足条件就改写 query 再检索（多跳、能纠错）——这正是面试官原话「封装成工具、按条件调用」。
- ⚠️ **Claude Code 代码定位没讲清**：被问「怎么定位到代码在多少行」时只说「工具调用 + 上下文拼接」。→ 正确：**Grep（ripgrep 正则）+ Glob + Read**，模型自主选关键词多轮迭代；**行号来自 Grep / Read 的带行号返回**（`cat -n` 格式），据此精确改那一段；不用向量 RAG，因为代码要**精确匹配**而非语义近似。
- ✅ 答得稳的：Agent 范式（ReAct / Plan-Execute / Reflection / Multi-Agent）、FC vs MCP、RAG 全流程、Claude Code 命令、compact 时机——基本能接住。
- ⚠️ **compact 时机**：我答「变笨了 / 上下文太多就压」，面试官补了更好的判断（记下来）：并行开多个 sub-agent 到处看代码后，等**调研出明确结论**再 compact、只留结论压掉中间过程；`/compact <重点>` 可指定保留；还能基于当前进度「分身」做另一件事。

**项目深挖**

- 围绕 MewCode 被追问的点：做它的动机（coding agent 通用性）、开发中发现的问题（① 上下文压缩边界 case：压掉 `tool_result` → FC 配对中断 + cache 不命中 → 模型反复调同一工具；② multi-agent 实测不稳超单 agent 的困惑）、框架（LangGraph 管状态、核心自己写）。
- 没接住的追问：MCP vs Skill、agentic RAG、代码定位到行号——都停在概念、给不出准确机制。

**反问环节**

- 问：在 AI Coding / Agent 领域可以朝哪些方面学习和改进？→ 面试官：① 跟前沿（规划型 Agent / Manus 类、deep research、闭环、自我进化 Agent），但**壁垒在变低**；② **结合业务、以产品价值为导向**，要补产品设计；③ 前后端壁垒被打破，往「**超级个体**」走，企业越来越不要「单纯的 Agent 开发」。
- 问：你觉得我今天面试哪里可以提升？→ 面试官：① 理论知识不用全背，但**核心思路 / 关键词要说清**；② 态度更**贴合业务和工业实践**，以产品价值为导向找项目丰富经历。

**结果 & 感受**

- 结果：待定
- 教训：
	- **概念要讲得清机制，不只是会用**：MCP vs Skill、agentic RAG、代码定位三处都是「知道大概、讲不准」→ 这三块按解答版背熟。
	- **agentic RAG 是这场的新考点**：workflow RAG vs Agent RAG（封装成工具、可反复调纠错）要能条件反射答出来。
	- **反复被强调「结合业务 + 产品价值」**：项目叙事里要加一层「解决了什么实际价值」，别只讲技术实现。
